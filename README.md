# ctex-talk

面向中文学术汇报的 **LaTeX/Beamer 模板与版式库**。固定的是研究问题—证据—结论的关系，以及图注和 take-home 的位置；不固定研究主题、配色细节或所有报告的页数。

本仓库只含通用模板、设计规范与占位图，不含真实研究数据或参与者记录。

## 从哪个文件开始

| 入口 | 适用场合 | 编译预览 |
|---|---|---|
| `template.tex` | 15–20 分钟、三问主线的完整实证研究汇报 | [template.pdf](template.pdf)：16 页正文 + 4 页附录 |
| `short.tex` | 10 分钟、两问主线的短报告 | [short.pdf](short.pdf)：10 页正文 + 1 页附录 |
| `layouts.tex` | 只取某种页面，或组织方法型/已有汇报 | [layouts.pdf](layouts.pdf)：14 页通用版式库 |

不是每次报告都应使用完整版。短报告通过减少问题和证据范围来压缩，不通过缩小字号来压缩。

## 快速开始

```bash
git clone https://github.com/shihuaidexianyu/ctex-talk.git
cd ctex-talk
./build.sh                 # 构建三个入口
./build.sh template        # 只构建完整模板
./build.sh short.tex       # 扩展名可省略
```

开始自己的汇报：

```bash
cp template.tex my-talk.tex
# 编辑 my-talk.tex，替换所有【占位符】
./build.sh my-talk
```

建议填写顺序：

1. 修改 `\title`、`\subtitle`、`\author` 和 `\date`。
2. 先写目录中的研究问题。
3. 为每个问题选择一张主证据图，填写结果标题、图注和 take-home。
4. 写结论页，再回头补任务、数据、测量与模型。
5. 删除不需要的可选页，不保留空占位符。
6. 构建并逐页检查最终 PDF。

**构建脚本会重建 `figures/placeholder.pdf`，不要把正式结果保存成这个文件名。**

## 完整模板的正文结构

| 页码 | 内容 | 页面任务 |
|---:|---|---|
| 1 | 封面 | 研究问题、对象、汇报人和一行样本信息 |
| 2 | 三问目录 | 用三个研究问题组织汇报 |
| 3 | 任务与现象 | 一张真实刺激 + 最少必要规则 |
| 4 | 原始数据 | 一条去标识化记录 + 字段与缺失信息 |
| 5 | 样本形成 | 顺序筛选与最终分析单位 |
| 6 | 分析流程 | 输入 → 模型/处理 → 输出 |
| 7–8 | 核心测量 | 定义、公式、例子、版本与边界 |
| 9 | 模型 | 一个核心公式 + 符号翻译 |
| 10 | 对照与评价 | 基线、新增信息、验证与防泄漏 |
| 11–13 | 三个结果 | 分别回答第 2 页的三个问题 |
| 14 | 三条边界 | 样本、测量与推断限制 |
| 15 | 三条结论 | 按相同顺序回答三个问题 |
| 16 | 结束页 | 保留核心结论后进入问答 |
| 17–20 | 附录 | 定义、数值核查和补充结果 |

短报告、两问目录、双图比较和其他组合见 `short.tex`、`layouts.tex`。

## 结果页已经固定在代码里

```latex
\fullfigureslide
  {【结论句标题】}
  {figures/result.pdf}
  {【横轴含义与单位】}
  {【纵轴含义与单位】}
  {【点、线、误差带与颜色含义】}
  {【唯一 take-home message】}
  {【模型、样本、区间与数据来源】}
```

生成顺序固定为：

```text
结论句标题
主图
图注：横轴 + 纵轴 + 点线颜色
Take-home message
来源 / 样本 / 区间口径
```

长标题或两行图注需要更多空间时，可调整图的最大高度，而不是缩小文字：

```latex
\fullfigureslide[.38\textheight]{标题}{图}{横轴}{纵轴}{编码}{结论}{来源}
```

图内仍必须保留坐标标题、单位和必要标签；图注不能替代缺失的坐标。流程图和任务图使用 `\visualnote{...}` 解释箭头、框和颜色，不伪造横纵轴。

## 用于现有汇报

不必重写已有 `main.tex`：

1. 把 `ctextalk.sty` 复制到现有 `.tex` 所在目录，并替换原来的样式包引用。
2. 保留已有任务、方法和结果内容，只把需要统一的结果页改成 `\fullfigureslide`。
3. 从 `layouts.tex` 复制缺少的页面；没有需要的页面时继续使用 Beamer 原生 `frame`、`columns`、`tabular` 和 `itemize`。
4. 若已有文档类使用 `fontset=ubuntu` 且本机编译正常，可以保留；新模板默认使用 TeX Live 自带的 `fontset=fandol`。

## 常用命令

| 命令 | 用途 |
|---|---|
| `\coverslide{...}` | 封面及一行样本定位 |
| `\agendatwo{问一}{问二}` | 两栏研究问题目录 |
| `\agendathree{问一}{问二}{问三}` | 三栏研究问题目录 |
| `\fullfigureslide[高度]{...}` | 标题—主图—图注—take-home—来源 |
| `\figurecaption{横轴}{纵轴}{编码}` | 数据图的固定图下注释 |
| `\visualnote{...}` | 流程、刺激或表格说明 |
| `\twopointslide{...}` | 两条结论 |
| `\threepointslide{...}` | 三条边界或三条结论 |
| `\lead{...}` | 非固定结果页的一句任务或读法提示 |
| `\takeaway{...}` | 带蓝色短线的唯一结论 |
| `\source{...}` | 可读的来源、版本与口径 |
| `\bignumber{数值}{标签}` | 关键数字 |
| `\flowbox{层级}{主体}` | 横向流程卡片 |
| `\sectionslide{编号}{标题}{路线}` | 章节或附录分隔 |
| `\closingslide{标题}{副句}` | 保留核心信息的结束页 |

## 构建环境

本机已验证：

- `ctexbeamer`，16:9、11pt、`fontset=fandol`；
- metropolis、Fira Sans、standalone；
- `latex + dvipdfmx`；
- Fandol 中文无衬线字体由 TeX Live 提供，无需系统 Noto/Ubuntu 字体路径。

临时文件位于系统临时目录，成功后清理；失败时保留日志目录。在线使用时可选择支持 ctex/Fandol 的 XeLaTeX 环境；本仓库的自动检查针对上述本机 DVI 工作流。

- [设计依据与规范复核](docs/MIT幻灯片设计建议.md)：MIT、W3C、SIGACCESS 来源建议与本仓库规则的区别。
- [默认汇报结构与变体](docs/固定汇报结构.md)：页面顺序、短报告和删减规则。
- [页面布局与填写指南](docs/页面布局与填写指南.md)：标题、主图、图注、take-home 和来源的位置。

MIT 指南不是统一格式认证；具体会议、课程和主办方的要求仍需单独核对。PDF 编译成功也不等于完整的可访问性合规。

## 图片与结果规范

- 优先插入矢量 PDF；原始刺激可使用 JPG/PNG。
- 按最终展示尺寸导出，避免插入后大幅缩小。
- 图内必须有坐标、单位和必要标签；图下必须解释横轴、纵轴与视觉编码。
- 一张图只保留本页所需系列、误差线和注释。
- 置信区间、预测区间、标准误和留出增益不能混用。
- 标题、图、图注、take-home 和来源必须来自同一版本结果。
- 口头报告应描述关键趋势与比较，不只说“如图所示”。

## 演讲备注

```latex
\note{口头解释与视觉描述放这里，不把页面写成逐字稿。}
```

默认构建不显示备注，也不增加 PDF 页数。完整定义、数值口径和问答材料放附录；需要可访问电子材料时，可同时提供讲稿或源文件。

## 提交或演讲前检查

1. 搜索 `【`，确认没有未替换的占位符。
2. 每页是否只有一个信息，标题能否独立表达该信息？
3. 目录问题、结果页和结论是否一一对应？
4. 每张数据图是否都有图内坐标与图下完整图注？
5. take-home 是否位于图注下方，并解释意义而非复读数值？
6. 是否没有 LaTeX 错误、未解析引用、overfull、裁切和标签碰撞？
7. 是否检查文字提取并逐页渲染，防止表格或图中内容消失？
8. 公开版本是否只包含有权公开的示例、聚合结果和刺激材料？
